# Interface languages

The Chrome extension interface is available in Traditional Chinese (Taiwan), English, and Japanese. This includes the settings page and the HUD's translated controls, status messages, and accessibility labels. Its language preference is stored with the extension's other local settings, so a manual selection is retained for the current Chrome profile.

This document describes the implemented extension behavior. It does not claim that the userscript or a live YouTube session has received browser acceptance.

## Choose a language

1. Open the YouTube CD HUD extension's options page.
2. In **Interface language**, choose **Automatic**, **繁體中文（台灣）**, **English**, or **日本語**.
3. Save the settings.

Choose **Automatic** to follow the browser's preferred language list. Choose one of the named languages to keep that language regardless of later browser-language changes.

## Automatic detection and fallback

Automatic mode examines the browser-provided preferred languages in order (the `navigator.languages` list).

| Browser-language match | Settings-page language |
| --- | --- |
| A language starting with `zh` | Traditional Chinese (Taiwan), `zh-TW` |
| A language starting with `en` | English, `en` |
| A language starting with `ja` | Japanese, `ja` |
| No supported or available match | Traditional Chinese (Taiwan), `zh-TW` |

For example, `zh-Hant`, `zh-TW`, and other `zh-*` preferences use the Traditional Chinese (Taiwan) interface. A missing, unsupported, or malformed saved choice returns to **Automatic**, which then follows the same fallback rule.

The extension reads browser language preferences; it does not change Chrome's language settings or the operating system language.

## Stored setting and scope

The choice is the `language` field in the existing `ytCdHudSettings` record in `chrome.storage.local`. The default is `auto`. Keeping the setting in the existing local record means it remains profile-local and follows the extension's existing reset and save behavior.

Translation covers the extension settings page and the HUD's visible controls and state text. Provider names, commands, CSS selectors, paths, source identifiers such as `YT` and `1001`, and user-entered custom CSS remain unchanged.

## For contributors

The supported persisted values are `auto`, `zh-TW`, `en`, and `ja`. Normalize a supplied language value before using it, and resolve `auto` only from the browser preference list. Keep the fallback at `zh-TW` so missing or unsupported browser preferences still produce a complete settings interface.

When adding a visible extension-interface string, add it to all three locale catalogs and preserve any HTML, field identifiers, commands, and CSS selectors that the interface depends on. Run the repository checks after changing implementation files:

```powershell
npm run check
npm test
```

Those local checks do not replace a visible Chrome, Tampermonkey, and YouTube acceptance check.
